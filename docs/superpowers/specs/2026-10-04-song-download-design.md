# 歌曲下载、歌词导出与文件管理设计

日期：2026-10-04

状态：用户已确认设计；已在 `feature/song-download` 实现，使用说明见 `docs/song-download-usage.md`。

## 1. 用户目标与约束

用户主要把歌曲保存到 TF 卡，在独立 MP3 播放器上收听；同时需要保存到电脑、U 盘或其他普通目录。功能不绑定设备品牌或型号。成功标准是能获得真正可播放的 MP3、配套歌词，并能批量下载、查找及删除保存的文件。

已确认的需求：

- 必须输出 MP3，接受转码产生的有损音频。
- 支持歌词下载及多种歌词格式。
- 支持单曲、多选和歌单批量操作。
- 支持实际文件删除，删除方式由本设计明确。
- UI 遵循项目已有 GTK4 / Libadwaita 风格。
- 保留 `Cargo.toml` 中 `adw` 的 `v1_5` 兼容调整。

本设计采用的默认值：192 kbps、44.1 kHz、双声道、固定码率 MP3；歌词默认原文 LRC / UTF-8；首次使用默认建议系统音乐目录下的 `NetEase Downloads` 子目录，系统未设置音乐目录时建议 `~/Music/NetEase Downloads`。初始建议经用户在下载对话框确认后才用于写入，后续记住最近使用的位置。

## 2. 方案与范围

采用应用级下载队列，加上按保存目录管理文件的页面。直接导出不能很好地管理整张歌单；完整离线音乐库会扩大到本地播放和曲库索引，超出本次用途。

第一版包括：

1. 单曲、所选歌曲、整个歌单或专辑下载，以及仅下载歌词。
2. MP3 128 / 192 / 320 kbps；基本歌名、歌手、专辑标签。
3. LRC、TXT、SRT 多选导出；原文、独立译文、双语三种组织方式。
4. 下载进度、取消、手动重试、重复任务去重及已有文件处理。
5. 选择保存目录、可选歌单子目录、可选文件序号、空间显示。
6. 持久化任务历史和独立文件索引；重启后中断任务由用户重试。
7. 目录内文件查看、多选删除、仅删除歌词、清除任务记录。
8. 显式扫描并纳入目标目录中原有的 MP3 文件。

第一版不包含音频断点续传、暂停恢复、自动镜像歌单并删除文件、格式化设备、自动清理重复音频、本地音乐播放入口、封面写入及 M3U 导出。下载到本地后复制到别处由文件管理器完成；软件可以直接把任意已挂载目录选为保存位置，不增加独立的设备同步系统。

## 3. 现有代码与需要补齐的能力

- `src/application.rs` 使用 `Action` 消息协调网络请求、页面和播放。
- `src/window.rs` / `src/model.rs` 已有页面栈、返回和 Toast 机制。
- `src/gui/songlist_row.rs`、`songlist_view.rs`、`songlist_page.rs` 可复用单曲入口、歌曲列表和歌单操作区。
- `data/gtk/` 存放 CompositeTemplate 布局；列表使用 `boxed-list`，行内按钮使用 `flat`，歌单主操作使用 `circular`，内容通过 `AdwClamp` 控制宽度。
- 首选项采用 `AdwPreferencesDialog`、`AdwPreferencesGroup`、`AdwActionRow` 和 `AdwComboRow`；设置使用 GSettings。
- `NcmClient` 能获取歌曲链接、原文与翻译；现有歌词方法同时写入桌面歌词目录，导出功能不能直接使用其副作用。
- 当前依赖的 `ncm-api` 2.2.0 在普通音质下请求 AAC，在无损音质下请求 FLAC；扩展名不能作为 MP3 判断依据。
- `SongUrl` 没有暴露源编码、试听范围等原始响应信息。歌单详情单次请求设为 1000 首，`PlayListDetail` 没有保留完整 track IDs 和总数。
- 依赖自带 `download_song` 会把整首文件读进内存，并且非成功 HTTP 状态不一定返回错误，不满足本设计的进度、取消及错误要求。
- 本机已经安装 GStreamer 的 `lamemp3enc` 和 `id3v2mux`。这只是本机可用性证据，运行时仍须检查需要的插件。

针对 API 缺失信息，实施时在项目内对当前 2.2.0 源码做最小兼容补丁，并通过 Cargo 本地 patch 接入：新增下载所需的响应类型、完整歌单 track IDs 和可取消的流式下载方法，复用原有认证、代理和加密请求。原有播放接口保持兼容。补丁、上游版本来源和许可一并纳入仓库，不修改 Cargo 缓存中的依赖副本。

## 4. UI：沿用现有风格

不引入侧边栏、网页式卡片、独立配色或设备向导。跟随已有浅色 / 深色主题，使用系统字体、symbolic 图标、原生控件和现有间距。产品界面使用“保存位置”“下载”“文件”等措辞，不展示内部任务 ID、媒体管线或 API 字段。

### 4.1 下载入口

- 歌曲行增加平面下载图标按钮及提示文字，点击打开下载设置对话框；不触发行激活和播放。
- 播放栏增加“下载当前歌曲”入口，使用相同对话框。
- 歌单 / 专辑头部在播放、收藏操作附近增加同风格的“下载全部”按钮；加载完整列表前不可用。
- 普通歌曲列表增加“选择歌曲”入口。进入选择模式后显示复选框、选中数量、“全选”“下载所选”“取消选择”。选择模式下点击行用于勾选，退出后恢复原有点击播放行为。
- 搜索结果的“全选”仅包含已加载结果，界面明确显示这一范围；“下载全部歌单”则必须获取完整歌单，不能把当前已显示条目当作全部。
- 歌单入口形成入队时的曲目快照；歌曲顺序和编号按该快照固定，不随之后的页面排序变化。

### 4.2 下载设置对话框

使用 Libadwaita 1.5 支持的 `AdwDialog`，按现有分组行组织：

- 保存位置：显示路径，通过原生文件夹选择器更改。
- 下载内容：音频与歌词 / 仅音频 / 仅歌词。
- MP3 码率：128、192、320 kbps，与播放音质设置独立。
- 歌词格式：LRC、TXT、SRT 独立勾选；启用歌词时至少选择一种。
- 歌词内容：原文 / 原文和独立译文 / 双语；编码 UTF-8 / GBK。
- 批量选项：按歌单建立子目录、给文件加序号；默认前者开启、后者关闭。
- 显示歌曲数量、可用空间及按已知时长估算的 MP3 大小；估算不包括精确歌词、标签和临时空间，不能作为写入必然成功的承诺。

主按钮为“加入下载队列”；仅下载歌词时隐藏音频码率设置。高级命名模板不进入第一版，使用固定且可解释的命名规则。

### 4.3 下载与文件管理页面

从现有主菜单的“下载与文件管理”打开，加入现有页面栈，复用返回按钮和底部播放栏。页面内设置“下载任务”“已保存文件”两个原生切换视图，不增加主导航标签。

任务视图显示歌曲信息、目的目录、阶段、进度和可用操作。阶段为等待、获取资源、下载、转换、保存、完成、已取消、失败、已中断。总览显示完成 / 失败 / 等待数量。大批量操作的失败细节留在列表中，Toast 只用于简短汇总。

文件视图顶部选择当前保存位置，提供搜索、刷新、扫描已有文件和进入多选。列表使用 `boxed-list` 和现有歌曲信息排版，显示歌词标记、大小、是否存在。单项或批量操作均来自同一套逻辑。空目录、目录不可用和无搜索结果使用原生状态页。

### 4.4 首选项与可访问性

首选项新增“下载”分组，保存默认目录、码率、歌词选项和命名选项。一次下载的选择成为后续默认值，已入队任务保持自己的参数快照。

新控件有可访问名称和键盘操作；复选状态、错误和进度有文本表达，不能只靠颜色。新增界面文案进入 gettext 和中文翻译，资源清单、Meson 源文件列表同步维护。所有新控件限制在 GTK 4.14 / Libadwaita 1.5 可用范围。

## 5. 音频生成和完整性

对歌曲使用当前登录与代理状态重新获取链接；不把播放缓存和缓存清理机制当成正式下载管理。

优先请求与输出码率匹配的普通音质：128 / 192 / 320 对应 Standard / Higher / Extreme。服务降级时显示实际源音质；选择 320 kbps 不意味着能提高较低质量的源音频。

先把源文件流式下载到电脑的应用临时目录，再检测实际媒体类型和完整性。源文件已经符合全部输出约束时，保留 MP3 帧，仅写入标签；不符合目标约束的源文件使用独立 GStreamer 管线解码、重采样、编码为固定码率 MP3。输出须验证为 MPEG Layer III、44.1 kHz、双声道以及所选码率，不能仅验证扩展名。

只接受完整歌曲：空链接、明确试听标记、非成功响应、解码错误或明显时长不足都不能成为成功音频。API 下载响应必须保留试听信息和预期时长；若没有可靠时长，则不给出完整音频成功状态。最终媒体时长与预期时长之差允许最多 `max(2 秒, 预期时长的 1%)`，并用真实编码样本验证该容差。合法短歌根据自身预期时长判断，不使用“超过 30 秒”之类的固定门槛。

基本标签使用 ID3v2.3，写入标题、歌手、专辑；选择编号时可写入文件所在下载快照的曲序。标签写入方式须支持版本选择，不能因为现成 muxer 仅有默认版本就放弃约束。缺少编码 / 解码插件时，在入队检查或任务行给出可操作的错误；歌词单独下载继续可用。播放管线和下载转换管线彼此独立。

## 6. 歌词导出规则

新建无桌面歌词目录副作用的获取与解析接口，保留原文和译文。歌词文件与音频共用基础文件名。译文独立输出时增加 `.translated`，例如 `歌手 - 歌名.translated.lrc`。双语模式在同一时间点排列原文和对应译文。

- LRC：保留时间标签，统一为 `[mm:ss.xx]`；一行多个时间标签展开成多个事件，按时间稳定排序。
- TXT：去掉时间标签，以行保存正文；双语时译文紧随对应原文。
- SRT：连续编号；每个事件结束时间取下一事件起点，最后一个事件使用歌曲时长，未知时长时延续 3 秒；同时间点内容合并为一个字幕，忽略非正长度段。
- 无时间标签的歌词仍可导出 TXT；LRC / SRT 分别标记不可用，不伪造时间轴。
- 原文存在但译文不存在时，保存原文并显示“无翻译歌词”；不生成空译文文件。
- 纯音乐或无歌词作为独立歌词结果显示，不把成功音频改成失败。
- UTF-8 不带 BOM，文本换行统一 CRLF；GBK 遇到不能编码的字符时明确报告该文件导出失败，并提供按 UTF-8 重试，不能静默替换为问号。

一首歌曲的音频和每个歌词文件有独立结果。已成功保存的音频在歌词失败、重试或取消时保留；用户可以只重试失败的歌词部分。取消不自动删除已经正式保存的文件。

## 7. 路径、重复与空间

默认基础文件名为 `歌手 - 歌名`，编号开启时为 `001 歌手 - 歌名`。编号宽度按快照总数取至少三位。歌单子目录使用歌单名，重名的不同歌单追加歌单 ID。

文件名替换路径分隔符、控制字符和 `<>:"|?*`，清理末尾点和空格，处理空名和常见保留名；对每一段按 UTF-8 字节数截断到 180 字节以内且不截断字符。始终在保存位置下面构造路径，禁止 `..` 逃逸。用户选定的目录先解析实际位置；后续不沿目录里的符号链接扫描、保存或删除。

重复规则：

- 同歌曲 ID、实际目标目录、码率、歌词参数和命名结果的活动任务去重；不同保存位置允许独立副本。
- 已索引且文件未变动的相同歌曲和输出参数，跳过已成功文件；新勾选的缺失歌词继续生成。
- 同歌曲但输出参数变化时保留两份，通过文件名附加码率或歌词编码区分。
- 未索引的同名文件，以及不同歌曲的同名冲突，保留原文件，新文件加歌曲 ID，仍冲突时加序号；同一批次提前预留名称。
- 第一版不提供覆盖已有文件。保存阶段也必须防止并发操作覆盖后来出现的文件，不能只在入队时检查存在性。

检查电脑临时目录和目标目录的空间。所有大文件操作流式执行。不能可靠估算源大小时仍在实际写入过程中处理空间不足，不能把未知大小视为零。

## 8. 本地目录与可移除介质

软件以目录为核心，设备检测只用于处理可移除介质的有效性，不要求型号。文件夹选择器仅支持本地路径的可写文件系统；网络 URI 不进入第一版，本地挂载文件系统按普通目录处理。

输出先在电脑完整生成，再向目标目录写入属于该任务的临时文件；复制期间检查取消和目录状态。同步文件数据后，通过不覆盖的提交操作改成最终名称，记录索引。音频和各歌词分别提交，不承诺多个文件的事务性原子保存。

对已挂载 TF 卡 / U 盘，记录挂载实例和卷标识；保存、扫描和删除前检查是否仍对应当前目标，复制过程中监听卸载。拔出后使该保存位置失效，不自动创建旧挂载路径，也不把排队任务重定向到电脑。重新插入后由用户确认 / 重新选择目录并重试。系统无法提供稳定卷标识时，使用本次会话挂载实例和文件系统标识；重启后要求重新确认可移除目标。

取消只清理任务拥有的临时文件；设备已离线时登记待清理临时文件，重新确认同一位置后再处理。不遍历删除其他 `.part` 文件。正常退出会取消工作、尽量清理临时文件并落盘任务状态；重新打开后任务标记已中断，不自动开始写卡。

## 9. 文件索引与扫描

数据保存在应用本地 DATA 目录，不向 TF 卡根目录写入数据库。版本化 JSON 存储包含保存位置、任务历史、独立的文件索引和待清理临时文件清单，采用临时文件替换方式更新并保留上一次可读版本。清除任务历史不清除临时文件清单，避免离线目标上遗留文件失去所属信息。

文件索引记录目录标识、歌曲 ID（若已知）、来源歌单、输出参数、相对文件路径、音频 / 歌词关联关系、文件大小和指纹；不保存登录 cookie、带签名的音频链接或长期可用的网络资源地址。清除任务历史不清除文件索引，所以后续仍可以正确管理文件。

扫描是用户主动操作，递归检查当前选择的根目录内的普通 MP3 文件，不跟随符号链接。读取可用标签，缺失时使用文件名；关联同目录同基础名的 LRC / TXT / SRT 和 `.translated` 变体，关联清单在纳入时展示。已有文件不推测网易歌曲 ID，不能仅凭歌名参与歌曲 ID 去重。

文件视图刷新时核对文件存在性及指纹；变动或被替换的文件显示“文件已变更”，删除前要求重新审阅实际文件清单。用户外部删除的文件标记缺失并可移除索引，不把缺失文件当成仍已下载。

## 10. 删除操作

| 操作 | 文件行为 | 记录行为 |
| --- | --- | --- |
| 取消下载 | 停止，清理本任务临时文件；保留已正式保存文件 | 保存取消状态 |
| 清除任务记录 | 不修改音频、歌词或临时文件 | 移除终态任务历史，保留文件索引 |
| 删除文件 | 删除选中的实际音频；默认包含已关联歌词，可取消勾选 | 按实际结果更新文件索引 |
| 仅删除歌词 | 删除所选关联歌词，保留音频 | 更新关联文件状态 |
| 移除缺失记录 | 不做文件操作 | 移除不存在文件的索引 |

删除前始终显示所在目录、具体文件清单、歌曲 / 歌词数量及预计处理字节数。优先使用系统回收站。预计处理字节数不能宣称一定释放磁盘空间：移到同文件系统的回收站可能不释放容量，界面明确提示；永久删除时才显示预计释放空间。

如果不支持回收站，确认按钮明确标为“永久删除”。批量执行中某项移入回收站失败时，该项保留并显示错误；不能静默回退为永久删除。用户可以随后发起新的永久删除确认。永久删除采用 destructive 原生按钮样式。

预览只包含已索引或显式纳入的普通文件；对照位置身份、文件指纹和规范化相对路径再执行。拒绝删除目录、越界路径、符号链接、已失效挂载上的文件以及被活动写入任务占用的文件。打开关联任务时可先取消，再重新发起删除。

音频 / 歌词逐文件处理并显示实际成功 / 失败数，部分失败不假装整体成功。没有文件删除事务或自动回滚。不同保存目录中的同歌曲副本分别处理，删除本地文件不修改网易云收藏或歌单。复用相同歌词文件的索引项必须在预览中展示受影响关联，不隐藏连带影响。

## 11. 模块边界与数据流

新增 `src/download/`，按职责组织，不把转换和文件逻辑塞进现有大型 `application.rs`：

- 模型：任务、选项、阶段、保存位置、文件关联和独立输出结果。
- 管理器：应用级队列，入队去重、取消、重试、进度汇总和持久化。
- API 适配：认证 / 代理快照、完整歌单枚举、音频信息、歌词获取及流式传输。
- 音频：解码、完整性探测、MP3 转换和标签。
- 歌词：解析、组织、LRC / TXT / SRT 格式化和编码。
- 存储：目录身份、命名与冲突、提交、索引、扫描及删除。

新增原生设置对话框和管理页面，通过现有 `Action` 通道触发入队 / 打开页面，用管理器事件更新 UI。Gtk / GObject 操作留在主线程；网络、媒体处理、目录扫描和大文件 IO 在后台完成。进度事件节流到每任务最多每秒四次，并保留最新状态。

初始并发限制为两个歌曲任务、最多一个编码管线；遵循 API 客户端已有连接限制。单项失败不阻塞后续任务。首版仅手动重试，重试时重新获取过期链接，保留已成功结果。账号退出或切换使待处理网络任务停止，用户重新登录后手动重试，避免账号状态混用。

流程：用户选择歌曲和输出参数 → 检查保存位置 / 插件 / 空间并预留名称 → 入队 → 获取完整音频与歌词 → 生成输出 → 校验 → 分文件提交 → 更新索引和各输出状态 → 页面汇总结果。

完整歌单流程先获得 track IDs 和总数，再按批获取详情，保留顺序。先核对原始 ID 列表长度和总数，再对重复歌曲 ID 保留首次出现的一项；入队界面展示实际独立歌曲数以及被去重的数量。未知 / 无法获取的歌曲形成可见失败项；只有数量核对一致才把枚举标为完成。接口不能证明完整性时报告失败，不展示“全部下载成功”。歌词无需随歌单详情预先拉取。

## 12. 错误处理与测试验收

错误必须区分资源不可用 / 试听、登录失效、网络失败、缺少插件、转换失败、歌词不存在、编码失败、目录离线、权限不足、空间不足和文件变更。详细信息留在任务 / 文件行，禁止把认证信息或签名 URL 写到用户可见日志。

自动验证重点：

1. 文件名净化、超长 Unicode、路径越界、同批命名预留、并发冲突和不覆盖保存。
2. LRC 多时间标签、异常时间格式、翻译对齐、无时间标签、SRT 末段和 GBK 编码失败。
3. 队列去重、部分输出重试、取消、重启中断、账号切换和状态持久化失败。
4. 本地生成的 AAC / FLAC / MP3 样本转换后探测为目标 MP3；验证标签、码率、采样率、声道和短歌完整性判断，不能依赖扩展名。
5. 本地模拟 HTTP 的失败状态、空响应、截断内容、过期链接、取消和进度；测试不依赖网易云账号。
6. 超过 1000 首的歌单响应样本、缺失详情和重复 ID 的完整枚举、顺序及数量核对。
7. 临时目标目录中测试音频与歌词关联、导入、文件外部变化、回收站失败无永久删除回退、部分删除失败和其他目录副本保留。
8. 模拟挂载失效、身份变化、空间不足和复制中取消；验证不重新创建旧挂载路径。

人工验收重点：

- 单曲、播放栏、歌单、专辑和搜索多选入口可用；多选不误触播放。
- 真实音频及同名歌词能从本地目录读取，并可保存到 TF 卡目录；按普通可移除文件系统工作，不声称验证所有播放器型号。
- 下载及转换期间仍可正常播放和切换页面；关闭管理页任务继续。
- 删除预览和实际操作一致；回收站与永久删除提示准确。
- 小窗口、浅 / 深色主题、键盘操作和中文文案沿用原有样式；对比现有歌曲列表和首选项进行实际界面检查。
- GTK / Libadwaita 兼容配置下构建，检查资源、schema、中文翻译和安装后启动；保留现有播放、收藏、搜索及登录行为。

所有删除验证只使用专门的临时测试文件。真实 TF 卡先验证保存、扫描及目录失效行为；不自动对用户已有歌曲执行删除测试。
